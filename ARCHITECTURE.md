# Architecture - auto-discription

> Auto-generated by `@auto setup --auto` on 2026-05-08. Keep this document as the durable map for future Autopus sessions.

`auto-discription` publishes the private npm package `@autopus/figma-read`. The system reads Figma frame data, creates schema-governed description manifests, lets a PM review and apply descriptions, and exposes the same read/write surface to external MCP clients.

## System Overview

```text
Figma file or fixture
  -> Read pipeline
  -> Description generation
  -> Description manifest
  -> PM Review UI
  -> Write Router
  -> Figma write-back

Figma plugin
  <-> WebSocket bridge
  <-> Autopus daemon
  <-> MCP stdio or HTTP/SSE
  <-> AI client
```

The current implementation is organized around completed SPEC-FIGMA slices for schema, read extraction, generation, review/write routing, daemon resources, stdio MCP, and loopback HTTP MCP. Tunnel/cowork transport code exists as an optional and partially verified track.

## Runtime Topology

`figma-read` can run against deterministic fixtures and produce a partial manifest. `generate-descriptions` reads frame input directories and emits a full description manifest using the mock, Anthropic, or OpenAI provider.

`autopus-daemon` owns local daemon state under `.autopus/`, including PID and runtime snapshots. It generates an ephemeral session token on start and avoids persisting that token to disk.

`autopus-mcp-stdio` hosts a long-running MCP server over stdio. It composes 4 read tools with 5 write tools in a fixed order and publishes 6 resources when write resources are enabled:

```text
Resources:
  autopus://active_selection
  autopus://pending_descriptions
  autopus://audit_events
  autopus://stale_frames
  autopus://pending_writes
  autopus://applied_writes

Tools:
  get_active_selection
  get_pending_descriptions
  get_audit_events
  get_stale_frames
  plan_emit
  dryRun
  approve
  apply
  undo
```

`autopus-mcp-http` hosts the same logical surface over loopback HTTP/SSE at `/mcp`. It defaults to `127.0.0.1`, requires `--allow-remote` for non-loopback binding, and isolates pending write state by MCP session.

The root TypeScript project excludes `apps/**`, `packages/**`, `tools/**`, and `vendor/**`; those surfaces have their own TypeScript configs or build commands. The root build runs the validator workspace build before compiling root sources.

`packages/redact-patterns` is the single source of truth for the four redact
pattern classes (`figd_`/`xoxb-`/bearer/absolute-path). Both the daemon redactor
(`src/daemon/redact-extended.ts`, via the `src/redact-patterns.ts` re-export shim)
and the write-router redactor (`packages/write-router/src/redactor.ts`) reconstruct
their regexes from it, preserving the SPEC-FIGMA-007 AC-S14 byte-equal parity
invariant by single-sourcing rather than duplicating literals. The captured prior
`node.annotations` snapshot is redacted on two independent retained-artifact paths:
the daemon `autopus://applied_writes` path (SPEC-FIGMA-018, `redactAndMinimizePrior`)
and the WriteRouter / Review-UI HTTP `/api/apply` path (SPEC-FIGMA-019,
`redactRestoreDescriptor` injection seam).

## Data Contracts

Manifest schemas live in `schema/description-manifest.schema.json` and `schema/frame-description.schema.json`. The dogfood examples in `samples/` and the deterministic 30-frame fixture in `fixtures/30-frame-mock/` are the primary oracle data.

Important manifest entry fields include `screen_id`, `display_id`, `title`, `intent`, `user_value`, `success_criteria`, `states`, `edge_cases`, `component_refs`, `data_io`, `design_tokens`, `variants`, `navigation`, `confidence`, `intent_mismatch`, `source_hash`, `write_target`, `persona_tags`, and `token_usage`.

Source hashes are computed from canonical node tree data and image bytes. Write idempotency is based on a manifest entry hash.

## Invariants

- Node runtime is declared as `>=22.0.0`; local setup observed Node `v24.14.1` and npm `11.14.0`.
- All public CLI bins use ESM and are built into `dist/`.
- `scripts/prepend-shebang.mjs` preserves executable shebangs after `npm run build`.
- MCP outbound text and audit-visible strings must pass through token redaction.
- Figma write mutation must be plugin-gated. A missing plugin bridge returns an error and emits partial-disconnect audit instead of mutating directly.
- `READ_ONLY_TOOLS` stays frozen as the 4-tool baseline; write tools are composed separately.
- Vendor code under `vendor/cursor-talk-to-figma-mcp/` is pinned source, excluded from root TypeScript compilation, and treated as out of scope for local source file size limits.
