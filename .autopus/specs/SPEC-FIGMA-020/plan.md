## 구현 전략 (Implementation Strategy)

- Additive composite, zero shared-path rewrite. The composite target is built from new modules (`structured-policy.ts`, `card-table-payload.ts`, `adapters/native-annotation-with-card.ts`, `plan-emit/native-annotation-with-card-plan.ts`) plus additive enum, map, and case entries. The existing `native_annotation` adapter and `annotation-card-plan.ts` are reused or left untouched, so the SPEC-FIGMA-018 and SPEC-FIGMA-019 invariants are preserved structurally rather than by promise.
- Reuse, do not reimplement. The native surface reuses `applyNativeAnnotation` and the `composeFrameLabel` and `composeAreaLabel` composers verbatim; the card surface reuses the placement and frame helpers in `autopus_area_handoff_renderer.ts`. Only the table-cell construction is new.
- D3 partial-failure is a daemon-apply concern. The write-router adapter composes the compound descriptor, but the native-committed-first, card-retryable, native-not-rolled-back guarantee is enforced where the plugin ops are dispatched sequentially (`src/daemon/apply-tool.ts`). T8 adds a focused branch for the compound variant so the generic partial-disconnect rollback (which stashes ALL completed commands) does not pull the native op back.
- File-size discipline. New modules are split by concern to stay under the 300-line project hard limit: the union normalizer (T2) is separate from the table-payload builder (T3); the composite adapter (T5) delegates composition outward; the renderer table helper (T4) is added to the existing vendor file but kept small and additive.
- Execution order. T1, T2, T3 (type and data shaping) precede T4 and T5 (surfaces), which precede T6 and T7 (wiring), which precede T8 and T11 (daemon and redaction), which precede T9 and T10 (schema and prompt) and T12, T13, T14 (surface, guards, tests). T9 can run in parallel with T2 and T3 since the union shape is small.

## Feature Completion Scope

This SPEC closes the requested feature outcome in full: a PM selects `native_annotation_with_card`, and one apply delivers the concise native annotation (anchored, Dev-Mode) AND a separate real-table policy card, with one compound undo reversing both and native-authoritative partial-failure semantics. No sibling SPEC is required; the structured-schema migration is an internal task group (T2, T9, T10) rather than a standalone SPEC because it produces no observable behavior on its own and the table builder depends on it directly. Deferred, non-required follow-ups (markdown-fidelity tuning, card layout theming, geometry-based area resolution) are itemized in `research.md` `## Completion Debt` and `## Evolution Ideas`, not hidden as vague future work.
