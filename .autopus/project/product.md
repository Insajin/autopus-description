## Product

`@autopus/figma-read` automates Figma handoff description work. It reads frame structure and screenshots, generates persona-tagged product descriptions, lets a PM review the output, and writes approved description artifacts back to Figma through a guarded route.

## Users

| User | Needs |
| --- | --- |
| Product manager | Review frame intent, user value, success criteria, and edge cases quickly |
| Designer | Keep Figma as the visible source of approved annotation and description context |
| Engineer | Consume structured implementation hints, data I/O, state, and component references |
| QA | Inspect edge cases, stale frames, and success criteria from one manifest |
| AI client operator | Query and apply descriptions through MCP without bypassing plugin consent |

## Value Proposition

The project reduces design-to-handoff documentation effort by converting Figma frames into a schema-backed manifest and making review/write-back auditable. The intended outcome is lower PM and design handoff overhead while preserving security controls around writes.

## Core Capabilities

- Extract frame metadata, screenshots, navigation, design tokens, and source hashes.
- Generate descriptions with mock, Anthropic, or OpenAI providers.
- Validate manifests against JSON Schema and deterministic fixtures.
- Review, edit, apply, undo, and audit write operations in a PM dashboard.
- Write descriptions as native Figma Dev-Mode annotations anchored to nodes, in addition to the free-floating annotation card.
- Deliver both surfaces in a single apply via the `native_annotation_with_card` composite target: a concise native Dev-Mode annotation anchored to the node plus a separate policy card that renders states, edge cases, data requirements, and area policies as real Figma auto-layout tables, with one compound undo and native-authoritative partial-failure handling.
- Expose read/write MCP resources and tools over stdio and loopback HTTP/SSE.
- Redact secrets and fence untrusted design text before prompts or wire output.

## Non-Goals

- Direct daemon-only Figma mutation without plugin confirmation.
- Treating vendored Figma plugin code as ordinary first-party source.
- Storing daemon session tokens on disk.
- Relying on live LLM, Slack, tunnel, or live Figma calls for unit-level determinism.
